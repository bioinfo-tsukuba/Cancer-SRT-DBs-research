# README

## Overview
This folder extends the **GSM-based error-sharing network analysis** performed in `../network` by incorporating **temporal information**, aiming to infer the timeline and potential flow of data among databases.

---

## File description

### 1. README.md
This file.  
It provides an overview of the folder contents and usage instructions.

### 2. Input files
Unlike the scripts in `../network`, this analysis **does not require** `chccsrtdb_analysis.xlsx`.  
Instead, the following files are required:

#### 2-1. `history_db.xlsx`
Contains, for each database, the **earliest known time of online availability**, collected from various sources such as preprint posting dates, journal publication history, Wayback Machine snapshots, and website update logs.  
Among them, the **earliest** date is stored in the `earliest` column, and the latest in `latest`.
Therefore, although `make_timecourse.py` internally selects the earliest date among them, 
the values in `earliest` are actually used in our case.


It also includes two types of inter-database relationships:  
- **citing** — other databases cited in the publication of this database.  
- **data_source** — databases used as data sources when constructing the target database.


#### 2-2. `db_panel_B_shared_error_summary.xlsx`
This file is an Excel version of the CSV file generated by running `../network/make_network.py`. 
For details, refer to the **Output files** section in `../network/README.md`.

It is used here to count the **number of shared GSM-level annotation errors** and to annotate or create edges between databases on top of the network structure derived from `citing` and `data_source` relationships in **2-1**.
When no such relationships exist for a given pair, the script may create a `heat_only` edge representing shared errors only.


#### 2-3. `pos_nudge.csv`
A manual adjustment file that allows fine-tuning of node positions (horizontal and vertical) in the resulting time-course network figure.  
The script can run without it, but using this file greatly improves visual clarity.  
Because the **y-axis has no inherent analytical meaning**, we manually adjusted **only the vertical offsets (`dy`)**, while leaving the **x-axis (`dx`)** unchanged although `dx` can be adjusted.

### 3. `make_timecourse.py`
#### 3-1. Description
**Target records**  
Using the `earliest` values from **2-1** as time coordinates, the script constructs a directed graph based on the relationships:  
- **citing** → drawn as **dotted lines** (from *cited* → *citing* database),  
- **data_source** → drawn as **solid lines** (from *source* → *user* database),  
and overlays **shared GSM-level annotation errors** between databases (from **2-2**) as a color-coded heatmap.

**Color and layout settings**  
- Color map
  - This color map corresponds to the number of shared GSM-level annotation errors and is used to visualize edges.
  - These edges can be created between databases even when no `citing` or `data_source` edge exists (i.e., `heat_only` edges).
  - Colormap: `Reds`  
  - Transparency (`alpha`): `0.7`  
  - Normalization mode: `HEAT_VMAX_MODE = "max"` 
  - A colorbar is displayed on the **right-hand side** of the figure.  
- Other layouts
  - In the current setting, The x-axis is drawn as an arrow by `XAXIS_AS_ARROW = True`.
    - These arrow settings are determined by the values under `Option to display x-axis as arrow`.
  - The x-axis represents database launch time and is divided by **gray yearly grid lines**, with the corresponding year label centered below each interval.  
  - The y-axis carries no analytical meaning—it is optimized only for visual separation of nodes.

> *Note*  
> In all cases examined in this study, when a database is listed as a `data_source`, it is also cited (`citing`),  
> so the **solid data_source line** takes precedence, and the **dotted citing line** is not displayed.

Node x-positions are determined by the `earliest` dates, while y-positions are adjusted through the **`time_optim` layout** algorithm (using parameters `NEAR_X_DAYS`, `MIN_Y_GAP_NEAR_X`, `Y_SPREAD_PASSES`, and `Y_SPREAD_COOLING`).  
Final positions are fine-tuned manually using **2-3** (`pos_nudge.csv`).

#### 3-2. Output files
All outputs are saved in `./db_graph_outputs/`.

| Output file | Description |
|--------------|--------------|
| **edges.csv** | Contains each source–target pair with both display names and internal keys (used in `pos_nudge.csv`), along with the edge types (`kinds` column: `citing`, `data_source`, `citing;data_source` or `heat_only`), edge count (`count`), and the number of shared errors (`shared_err_count`). |
| **nodes.csv** | Lists databases with their internal keys and corresponding `earliest` dates. |
| **graph.gpickle** | A NetworkX graph file (pickle-based format). It can be reloaded in Python to inspect node and edge attributes (e.g., `earliest`, `kinds`, `shared_err_count`). | 
| **pos_nudge_audit.csv** | When `pos_nudge.csv` is used, the script also exports `pos_nudge_audit.csv` in `db_graph_outputs/`, which records how each manual offset (`dx`, `dy`) has been applied (or skipped). |
| **timeline_network.png / .svg** | The resulting time-course network figure in PNG and SVG formats. |

> *Note*  
> This script includes some optional parameters. 
> The behavior of these alternative modes has **not been tested** and we recommend not to change the mode from the default settings.  
> e.g.
> - **LAYOUT_MODE**: In addition to the `time_optim` mode used here, the script supports `barycenter`, `hierarchy`, and `spring`.  
> - **CREATE_NODES_FROM_ERRORS**: 
> When `True`, nodes that appear only in `db_panel_B_shared_error_summary.xlsx` (i.e., not listed in `history_db.xlsx`) are added to the graph.  
> Since these nodes have no valid `earliest` date, they are placed at a default x-position slightly earlier than the earliest dated database (30 days before the minimum `earliest`).  
> In our dataset, such nodes do not occur, so keeping this option enabled does not affect the resulting figure.  
> - **WRITE_AUDIT**: When anomalies are detected (e.g., malformed database names or missing references), reports are exported as separate CSV files in `db_graph_outputs/`.  
>   Default = `True`. No files are generated if no anomalies are found.  
> - **EXPORT_SVG**: Exports an additional SVG file along with the PNG output (Default = `True`).
> We edited these SVG files in Inkscape to manually adjust label positions for clarity.

#### 3-3. Usage

```bash
# Run in VS Code terminal, with both make_timecourse.py and
# history_db.xlsx, db_panel_B_shared_error_summary.xlsx, pos_nudge.csv in the same folder
python3 make_timecourse.py

```
